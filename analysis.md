## 1. Executive Summary

This is a **pnpm 9.15.0 + Turborepo monorepo** containing one shipping product: `apps/firm-website`, a **fully static Next.js 15.5.22 marketing site** for YDM Agency. All content (services, blog posts, education lessons, FAQs, industries, pricing copy) lives in static TypeScript data files under `apps/firm-website/src/lib/` — there is no CMS, no database reads, and **zero API route handlers**. The only dynamic surface is **three** Server Actions: `/contact` and `/audit` (backed by Supabase, Resend, Upstash) plus `education/search-actions.ts` `searchLessons` (a pure in-memory filter over `EDUCATION_LESSONS`, called by the debounced `EducationSearch` box). Client-side interactivity is limited to 29 `'use client'` files (20 in the app, 9 in shared packages).

The repo is in good structural shape: a real workspace dependency graph, centralized version catalog, shared configs, meaningful test coverage, and CI. The main problems are **dead weight** (a broken excluded package, an unused test-utils package, ghost directories, duplicate tests), **CI gaps** (no unit-test job; a Playwright browser mismatch; `push` trigger targeting a branch that doesn't exist), and **materially stale documentation** (`AGENTS.md`/`README.md` disagree with the code on 13 points — see §11).

## 7. Backend Integration (verified in `app/contact/actions.ts`, `app/audit/actions.ts`)

Both actions share the same pipeline, duplicated across the two files:

1. `schema.safeParse(data)` — Zod; honeypot enforced schema-side (`_honeypot` must equal `''`).
2. **Rate limit**: `Ratelimit.slidingWindow(5, '1h')` over `Redis.fromEnv()`, keyed on `x-forwarded-for` (fallback `x-real-ip`, then `'unknown'`). Constructed only when Upstash env vars exist; **fails open** on Redis errors.
3. **Storage**: `createClient(NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY)` → insert into `leads` (`name`, `email`, `project_type`, `message`, `source` `'website'`/`'audit'`, `status: 'new'`, `created_at`). **Fails closed** when Supabase env vars are missing.
4. **Test seam**: `RESEND_API_KEY === 'test'` → `{ success: true }` after storage attempt (also masks storage failures during E2E).
5. **Email**: `sendEmail({ name, email, projectType<label>, message, type: 'contact'|'audit' })`.
6. Storage errors are **non-blocking** — submission still succeeds and emails still send (deliberate per `WHY:` comments, but means lead loss is possible while reporting success).

A third Server Action exists outside this pipeline: `searchLessons` in `education/search-actions.ts` — a pure substring filter over `EDUCATION_LESSONS` (no external services), invoked by `EducationSearch` after a 300ms debounce.

## 8. Security Posture

`src/middleware.ts` sets, on all non-static responses (matcher excludes `api`, `_next/static`, `_next/image`, `favicon.ico`, `og-image.png`):

- **CSP**: `default-src 'self'`; `script-src 'self' 'unsafe-inline' 'unsafe-eval'` + GTM/GA4/`connect.facebook.net`/`*.posthog.com`/`va.vercel-scripts.com`; `style-src 'self' 'unsafe-inline'`; `img-src`/`connect-src` cover GA4/GTM/doubleclick/google/posthog/facebook/graph.facebook; `frame-src 'self' https://calendly.com`; `font-src 'self' fonts.gstatic.com data:`; `worker-src 'self' blob: data:`.
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`.

**Findings:**
- Docs claiming "analytics scripts are blocked by the CSP" are **stale** — the CSP explicitly whitelists all three providers and allows `'unsafe-inline'` (required for JSON-LD and the new FOUC script).

## 10. CI / CD

`.github/workflows/ci.yml` — triggers: `pull_request` (all branches) and `push` to **`main`**.

Jobs: `changes` (dorny/paths-filter on code files) → `lint` (`turbo run lint`), `typecheck` (`turbo run typecheck`), `build` (`turbo run build --filter='...[origin/main]'`, `fetch-depth: 2`), `e2e` (installs **chromium only**, runs `playwright test`). `TURBO_TOKEN`/`TURBO_TEAM` env vars are wired for remote caching.

**Findings:**
1. **Push trigger targets `main`, but the repo's only branch is `master`** (local and `origin`). Pushes to `master` never fire the `push` event — CI only runs on PRs. Also, `--filter='...[origin/main]'` references a nonexistent ref for the affected-build filter.
2. **No unit-test job** — `pnpm test`/`turbo run test` absent; the whole vitest suite has no CI gate.
3. **Browser mismatch** — config runs chromium+firefox+webkit; CI installs only chromium → the e2e job will fail on missing firefox/webkit executables (or has never run green across all three).
4. `build` job's `fetch-depth: 2` may be too shallow for `...[origin/main]` diffs on older PRs.
5. No format check, no dependency audit, no deploy job (Vercel presumably handles deploys externally — not configured in-repo).
6. App lint uses `next lint` (deprecated; removed in Next 16) over a **legacy `.eslintrc.js`** while ESLint 9 defaults to flat config — works today via `eslint-config-next`, but is a fragile edge to verify when upgrading.
7. `turbo/generators/config.ts` defines a `new-app` generator referencing `templates/app/**` — no templates exist, so it can't scaffold anything.
8. **paths-filter coverage gap** — the `changes` job only watches `apps/**/*.ts(x)`, `packages/**/*.ts(x)`, `turbo.json`, `package.json`, `pnpm-lock.yaml`. Changes limited to `e2e/*.spec.ts`, `playwright.config.ts`, `vitest.config.ts`, `globals.css` (`.css` isn't matched), `*.js` config files (`next.config.js`, `tailwind.config.js`, `.eslintrc.js` — only `.ts/.tsx` match), `pnpm-workspace.yaml`, or `.github/**` **do not trigger CI at all** — every downstream job gates on `changes.outputs.code`.
9. **Unused turbo tasks** — `turbo.json` defines `test` and `e2e` tasks, but CI invokes `pnpm playwright test` directly and never runs the test suite at all; the `e2e` pipeline task is dead config.
